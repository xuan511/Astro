## 先把问题写下来

遇到一个不理解的现象，最容易做的事情，是立刻搜索答案。但还有一个很朴素的方法：先用自己的话，把眼前的事情说清楚。

- 我原本以为它会怎样？
- 实际看到了什么？
- 我做过哪些尝试？

把这三件事写下来，往往就能找到一个可以验证的方向。

## 一次只验证一件事

假设一个程序没有按预期运行，可以先缩小范围，而不是一次改动很多地方。

```c
#include <stdio.h>

int main(void) {
    int value = 42;
    printf("value = %d\n", value);
    return 0;
}
```

这个例子很小，但小也有小的好处：输入、过程和输出都在眼前。

> 让每一次尝试，都能告诉自己一点新东西。

## 留下一份能看懂的记录

记录不一定写得漂亮。写下背景、现象、尝试和结果，过一阵子回头看，仍然能够复现，就已经很有用。

| 记录什么 | 为什么保留           |
| -------- | -------------------- |
| 预期结果 | 明确判断的标准       |
| 实际现象 | 保留观察的证据       |
| 最小改动 | 知道什么产生了影响   |
| 验证结果 | 为下一次尝试提供依据 |

不急着把所有问题一次解决。今天弄清楚其中一个，也算往前走了一点。
