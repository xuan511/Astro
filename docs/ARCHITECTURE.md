# 架构与取舍

本文记录渐进改造的职责边界、问题依据与开源参考。2026-11-13 的展示层规范见 [设计系统](DESIGN.md)；实际检查结果、浏览器操作和部署状态另见 [阶段验收](ACCEPTANCE.md)，不沿用上一轮的测试数量或性能评分。

## 总体结构

拾间继续使用 Astro、TypeScript、Content Collections 和 Markdown / MDX，在构建时生成静态 HTML。站内导航使用 Astro ClientRouter；浏览器脚本负责搜索、主题、阅读辅助、项目速览、音乐以及文章讨论。文章正文来自内容集合。交互数据由独立部署的 Django API 和 SQLite 管理，接口与数据同步步骤见[文章讨论](COMMUNITY.md)。

```text
仓库内容 / 站点配置
        ↓ 校验与读取
Content Collections / lib/content
        ↓ 纯派生规则与路径
页面路由 / 卡片 / 布局 / 搜索索引 / RSS
        ↓
静态 HTML、资源与 Sitemap → GitHub Pages 或其他静态主机

浏览器：站点偏好 + 页面交互 + 单实例持久播放器
```

目录按职责划分：

| 位置                                                   | 职责与边界                                                                                 |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| `src/config/site.ts`                                   | 品牌、简介、导航、联系方式和默认主题；不放浏览器状态或构建产物。                           |
| `src/content.config.ts`、`src/content/`、`src/data/`   | 校验文章、项目和随记，保存真实内容；草稿规则不能只在页面模板中处理。                       |
| `src/lib/content.ts`                                   | 读取 Content Collections，向消费者提供已发布文章与按时间排序的随记。                       |
| `src/lib/post-query.ts`                                | 纯文章查询：公开过滤、稳定排序、栏目筛选、分类标签分组、邻篇与年度归档。                   |
| `src/lib/dates.ts`                                     | 统一上海时区的日期格式化与年/月/日投影；不依赖构建主机时区。                               |
| `src/lib/paths.ts`                                     | 站内路径与部署前缀；外部资源地址透传。日期与内容分组使用各自的纯逻辑模块。                 |
| `src/lib/indexing.mjs`                                 | 页面是否允许索引的共享策略，同时供 Astro 页面元数据与 Node 构建配置使用。                  |
| `src/components/SeoHead.astro`                         | 标题、描述、Canonical、分享元数据与 robots 标签；不承担内容读取或页面渲染。                |
| `src/layouts/Base.astro`                               | HTML 外壳、导航、页脚、全局搜索与唯一播放器；页面内容进入主区域。                          |
| `src/pages/`                                           | 文件路由、静态路径和页面组装；使用共享数据规则，不各自决定日期与索引政策。                 |
| `src/lib/dialog.ts`                                    | 原生对话框能力检查、互斥、关闭与焦点恢复；搜索、阅读、项目分别管理自己的初始化与销毁。     |
| `src/lib/theme-preferences.ts`、`src/scripts/theme.ts` | 纯主题决策与防闪烁启动脚本、会话内浏览器控制器；`site.ts` 只导入主题入口，不重复实现规则。 |
| `src/scripts/`                                         | 客户端交互；全局状态与临时页面 DOM 的生命周期分开。                                        |
| `scripts/`                                             | 构建期内容转换、部署配置、迁移与产物验证；不进入浏览器运行时。                             |

`indexing.mjs` 使用 JavaScript 模块，是为了让 Node 配置和 Astro 应用消费同一份规则，避免依赖构建器才能读取策略。浏览器交互与内容派生保留 TypeScript 类型。

| P1     | 快捷搜索用 `event.target === dialog` 判断背景点击；点击对话框内部的留白也以 dialog 为目标。                                                            | 用户点击搜索面板内边距会意外关闭。                       | 共享控制器结合元素矩形判断边界；测试面板内留白保持打开、真正背景点击关闭。                                    |

## 数据与索引约定

文章是否公开由内容查询层决定；页面、RSS、搜索索引和分类标签等入口消费相同的已发布集合。公开仓库内的草稿源文件仍然可见，草稿开关不提供保密能力。

日期显示和归档按 `Asia/Shanghai` 解释，避免本地 Windows 与 Actions 的主机时区改变结果。ISO 时间戳仍保留其原始语义；这轮不增加定时发布策略，也不把未来日期自动当草稿。

内容分组与排序是纯派生逻辑，不缓存 `getCollection()` 的长期结果。这样本地写作更新不受模块级内容缓存影响，测试也不必启动 Astro 才能验证规则。

`publishedPosts(kind?)` 只做读取与委托，`selectPublishedPosts()` 过滤草稿、按发布时间倒序排列，同一时间使用 ID 稳定排序。分类与标签使用 `groupPostsByTaxonomy()`，同一文章的重复标签只进入分组一次；邻篇使用 `postsWithNeighbors()`，继续沿全站已发布文章排列，未擅自改为同栏目邻篇。`groupPostsByYear()` 使用 `calendarDate()` 的上海日历日期生成归档，`paths.ts` 暂时重导出 `formatDate()`，以兼容已有消费者。

索引策略同时覆盖根路径和项目子路径。搜索与写作指南继续可访问、可导航，但不向搜索引擎推荐索引；Sitemap 与 robots 元数据从同一规则推导。404 和旧版恢复页面继续排除。修改索引规则后应同时检查 HTML、Sitemap、RSS、搜索索引与草稿隔离，不能只修改一个 `<meta>` 标签。

## 浏览器生命周期

Astro 客户端导航不会重新启动整个浏览器会话。模块只执行一次、页面 DOM 会替换、`transition:persist` 节点会保留，这三者不能混为一体。

| 范围                     | 状态归属与清理方式                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 主题                     | 会话内保存偏好；存储成功时持久化。首次绘制先设置主题，后续页面切换同步新文档和按钮；显式选择与跟随系统分开。                                   |
| 搜索、项目速览、阅读辅助 | 页面加载时查找当前 DOM 并初始化，离开前解除监听和观察器、取消延时与动画帧。                                                                    |
| 对话框                   | 共享 `createDialogController` 管理原生模态行为；调用方决定初始焦点、关闭入口和功能清理。正常关闭恢复入口焦点，换页销毁不把焦点拉回离开的节点。 |
| 音乐                     | `Player.astro` 的 `transition:persist` 保留一个播放器和一个 audio，控制器只绑定一次；不能由页面交互初始化反复创建。                            |

原生 dialog 承担模态语义和浏览器焦点约束，共享层补足能力检查、弹层互斥和退出边界。不要为每个功能再实现一套不同的 Escape、背景点击或焦点恢复逻辑，也不要在共享控制器里读取搜索词、图片数据或项目资料。

刷新后音乐仍需用户主动播放。验证连续播放必须观察实际 audio 实例、暂停状态与时间推进，不能只看按钮图标。

2026-11-18 按 [XHBlogs 参考说明](XHBLOGS-REFERENCE.md) 迁入卡片矩阵与毛玻璃展示。`HomeMusic` 是现有 Player 的另一组控件，`HomeSpotlight` 只负责当前页手动精选切换；`Appearance` 持有一个原生弹层和背景节点，纯偏好校验留在 `lib/appearance-preferences.ts`。原 120ms 转场、搜索缓存、进度节点缓存与唯一音频保留。

## 日常维护检查

工程质量以可执行约束验收，而不是以文件数量、抽象层级或“工程级”的自称验收：

- **依赖方向可检查。** 内容读取留在 Astro 服务端，纯逻辑不读取 DOM 或运行时 Astro API，浏览器功能不直接读取 Content Collections 或站点服务端配置。类型导入与运行时导入需要区别识别，不能用正则把 `import type` 当成浏览器依赖。
- **持久状态有唯一所有者。** Base 中的播放器与持久节点契约要受保护；搜索、图片与项目弹层不能再创建播放器。页面离开时清理页面监听，保留音乐控制器。
- **失败会阻止交付。** 类型、格式、单元行为、生产构建、产物一致性与部署路径检查必须显式失败，不通过删除断言、跳过测试或改低要求获得通过。
- **测试对应边界。** 日期验证跨日跨年与不同主机时区；内容验证草稿、空集合和同日顺序；主题验证非法存储与禁用存储；弹层验证互斥、边界点击、能力降级和销毁后的焦点。
- **构建与部署结果分开记录。** 本地预览、源码提交和成功构建都不能证明 Pages 已上线。CI 应检查根路径、项目子路径和自定义域名，部署状态以实际任务与输出网址为准。

### 当前门禁范围

`npm run check:architecture` 使用已安装的 TypeScript AST 检查两类客户端入口：`src/scripts/` 中的源码，以及所有 `src/` 下 Astro 文件中的原生非 JSON 脚本块。组件脚本带有独立虚拟标识，但错误定位保留真实组件文件与行号，相对导入仍按组件目录解析。扫描跳过 frontmatter、模板注释、样式正文、`application/json` / `application/ld+json` 数据块；自闭合 `set:html` 启动脚本没有静态正文，不会吞入后续脚本。静态本地 `script src` 会沿同一依赖图检查，表达式 `src`、动态 `type` 和展开属性等无法可靠分析的形式会明确失败。

门禁递归检查运行时静态导入、重新导出与字面量动态导入，忽略纯类型依赖。浏览器入口只允许依赖 `src/scripts/` 与纯 `src/lib/`；`content.ts`、`music.ts` 适配器、配置、数据、页面、布局、内容目录和 Node / 服务端 Astro 模块不能进入此依赖链。未知别名、无法解析的本地路径、语法错误、非常量动态导入、`require`、`import.meta.glob` 与不支持的本地源码类型均报告失败。正常裸 npm 包由现有构建器验证，门禁不扫描 `node_modules`，也不以静态字符串规则推测 DOM 或播放器唯一性。

`check:architecture` 已接入 `npm run verify` 和 CI build。CI 的独立 paths 作业执行根路径、项目子路径与自定义域名预检，正式 deploy 必须等待 build 与 paths 均通过；PR 同样执行这些路径检查。

修改内容派生、路径或索引政策后，执行项目现有 `npm run verify`；涉及部署前缀再执行 `npm run verify:pages -- --repo=xuan511/Astro`。修改客户端生命周期后，补充针对状态恢复和清理的测试，并在生产预览中完成导航、弹层和音乐回归。

不在这份架构文档固定测试数量、页面总数、Lighthouse 分数或上线地址。这些是每次构建的观测结果，记录在验收文档与对应的 CI 运行中。源码上传、云端构建和正式部署分别核实。
